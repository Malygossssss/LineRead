# 微信读书当前页精确读取设计

## 目标与边界

LineRead 不再把微信读书强制切换为纵向滚动，也不再启动后扫描完整章节。程序将微信读书横向阅读器一次展示的单页或双页画面统一视作“当前页面”：启动、重新打开和切换书籍时只读取该画面，按视觉顺序生成单行阅读单元，并始终从当前页面第一行开始。LineRead 不保存书籍、章节、页码或行号；微信读书仍是跨设备进度的唯一来源。公开页面目前没有稳定的“第 N 页 / 共 M 页”字段，因此阅读详情只显示当前章节和当前页面内的行进度。

翻页采用双向按需加载。用户在当前页面末行继续向后滚动时，后台点击微信读书“下一页”，等待公开渲染内容确实变化，再读取新页面并从第一行开始；在首行继续向前滚动时点击“上一页”，读取成功后定位到上一页面最后一行。正常的页内逐行导航不操作浏览器。目录选择、上一章、下一章继续使用目录控件，完成后读取目标章节的当前首屏并定位第一行。

## 组件与错误处理

`WeReadController` 负责确保横向布局、提取当前可见 DOM/Canvas、生成页面渲染签名并点击翻页控件。Canvas 只读取当前渲染容器中的画面，不再从章节顶部向下滚动；多个 Canvas 按页面渲染顺序识别并拼接。`WeReadSource` 继续把提取结果转换成 `WeReadChapter`，但其中 `units` 的含义调整为当前页面单元。`WeReadIntegration` 在原有单线程 Playwright 执行器上增加异步翻页任务，避免 Qt 界面阻塞。`DesktopReader` 在页面边界发起翻页、显示加载状态，并在失败时恢复原页面原行。

翻页按钮不可用、渲染内容未变化或 OCR 失败时，悬浮窗保留旧内容并提示错误；不会伪造页码，也不会把临时页面位置写入 `config.json`。测试覆盖横向布局切换、当前页 Canvas 读取、双向翻页、异步线程、页面边界定位、阅读详情文案以及原有章节功能回归。
