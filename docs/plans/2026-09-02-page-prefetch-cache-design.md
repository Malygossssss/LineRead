# 微信读书页面预取与缓存设计

## 目标与边界

LineRead 在用户阅读当前页面时，后台预取下一页面并把显示用的
`WeReadChapter` 快照保存在内存中。用户越过页面边界时，若相邻快照已经
就绪，悬浮窗立即切换，不再等待网页翻页和 OCR；后台随后把微信读书页面
位置同步到新的显示页并继续预取。

缓存仅在当前进程内有效，最多保留五个相邻页面，不写入 `config.json`，
也不伪造微信读书没有公开提供的页码。上一页由已读快照自然形成，启动后
只主动预取下一页，避免同时向两个方向翻页和 OCR。快速翻页超过预取速度、
首次随机章节跳转、边界不可用或预取失败时，继续使用现有按需加载流程。

## 组件与数据流

`WeReadIntegration` 维护逻辑页面索引、浏览器实际页面索引、页面快照字典
和预取任务。所有 Playwright 操作继续由现有单线程执行器串行运行，避免
跨线程访问同步 Playwright 对象。主界面收到启动或章节切换结果后调用
`prime_page_cache`：当前快照成为索引 0，随后排队执行低优先级前向预取。

预取执行 `当前页 -> 下一页 -> 提取/OCR -> 返回当前页`，只有返回成功后
才发布缓存。因此正常空闲状态下浏览器位置仍与悬浮窗一致。缓存命中时，
`page_ready` 在调用线程立即发出，用户先看到新页；单线程工作器再把浏览器
移动到该页。缓存未命中时，工作器在执行前再次检查缓存，以复用排队期间
刚完成的预取结果。

`WeReadController` 额外维护小型 Canvas OCR LRU。相同像素哈希再次出现时
直接复用识别行，减少返回旧页或重新进入已见页面的计算。

## 失败处理与测试

预取失败不会弹窗，也不会替换当前显示内容；按需翻页失败仍沿用现有错误
提示。预取向前移动后无论提取是否成功都尝试返回，返回失败时使该轮缓存
失效，后续按需操作重新同步。章节、书籍或手动重新载入会建立新的缓存代次，
旧任务结果不得写入新代次。

测试覆盖：预取完成后浏览器返回原页、缓存命中同步发出结果、已读页可立即
后退、未完成预取时按需路径仍工作、缓存容量限制、旧代次结果丢弃，以及
Canvas 像素哈希跨调用复用 OCR。完整测试套件用于验证原有启动、章节、翻页
和 UI 加载状态不回归。
